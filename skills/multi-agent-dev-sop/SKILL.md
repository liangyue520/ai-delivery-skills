# 多智能体协作开发与交付SOP

流程版本：4.2；更新日期：2026-11-02。按授权和宿主规则组织代理及委派相关聊天；保留原技能名和引用路径。

## 执行约定：所有项目适用

先应用 [delivery-first](../delivery-first/SKILL.md)。本技能的所有流程、模板、案例和兼容入口均遵守该约定，不保留“其他项目不变”的例外。

- 主聊天统一负责目标、协调、集成和交付；在用户授权和宿主规则允许时，可按需委派智能体、开发代理或相关Work完成开发、修复、分析、审查与验证。已有授权在其范围内无需逐次重复确认，委派不扩大业务范围、数据访问或外部操作权限。
- 小任务和紧密关联的修改直接连续完成，独立任务按预期收益并行。明确执行范围，避免相互覆盖和争用资源；不按任务数量强行扩充代理，不默认设领域负责人、顾问、独立QA或评测门槛。跨Work优先复用相关聊天，新建Work仍遵守用户明确创建要求及工具规则，不经外部CLI/API绕过权限。
- 不做内部人类授权身份核验、分发确认、已读回执、窗口准入、冻结审批和日常哈希/字节审计。业务账号权限、工具限制、必要业务验证与真实数据保护继续有效。
- 已有原型直接作为界面规格，优先复用现有系统、布局、导航、字段和交互；只补当前需求缺口，不重新推导界面或因偏好换栈。
- 过程材料仅保留简短任务说明和必要验收证据，不强制建立任务树、批次、角色交接、能力盘点和设计冻结材料。用户明确要求的文档正常交付。

## 按任务读取

- 接手、拆解或实施：读 [workflow.md](references/workflow.md)，复用现有成果，由主聊天组织补缺口。

- 需要可复制指令：读 [prompts.md](references/prompts.md)，按本轮目标填写；模板不提供额外授权。
- 验证、缺陷修复或交付汇报：读 [status-and-evidence.md](references/status-and-evidence.md)，只保留必要证据。
- 仿真、实时状态、统计或评估：按需读 [runtime-contracts.md](references/runtime-contracts.md)，核对真实业务数据。

- 验收时按影响选用 [checklist.md](references/checklist.md)，不要求逐项填全。

## 从任务到成果

定位可复用入口 → 明确当前目标与业务成功标准 → 补必要设计和数据规则 → 主聊天自行或委派实施并统一接入正式入口 → 按需部署必要服务 → 验证受影响业务 → 说明成果、实际验证和重要未完成项。

需要分阶段时，每阶段交付能操作的完整流程。小改动可直接实施和验证；不强制先建任务卡或先走设计阶段。已有可靠原型、设计、接口或运行能力直接复用，不重复建设。

主聊天负责集成、查漏并组织修复，核实执行者返回的实际改动和验证证据；不能将代理完成或独立模块自测当作整体交付。修复后做受影响回归，通过即可据实更新状态，不要求另一个角色签字；用户指定的验收按其范围执行，不重建审批链。

## 真实验证与停止

- 区分已实现、接入正式入口、实际验证和用户验收；不以独立Demo、构建成功、健康探针或“已完成”文字替代必要业务检查。
- 自检、实际独立审查和用户认可分开。主笔或实施者不能预填其他执行者的通过报告；主控可原样保存真实返回，但须核对实际执行来源、对象版本与证据。文件名、角色名、自填任务ID或高分不证明独立性；没有实际验证就保留未验证状态。
- 连续自动任务由一个调度者推进，事先确定可执行的工作量或轮次边界；不自发递归续跑，不重复唤醒运行中的任务，不通过重置计数或换聊天绕过边界。普通一次性任务不为此新增台账。缺计费数据时不承诺金额或额度百分比上限。
- 样例、mock、回放、真实运行、人工修正标明来源；缺失值不填零，不虚构公式或结果。
- 核对实际运行入口和受影响数据；保护现有修改与数据库记录。错包、漏编先修构建和启动入口，再直接验证功能，不默认增加冻结副本或全包比对。
- 根据改动确定最小充分验证。通过后不无依据重跑未受影响检查，不因省额省掉必要测试。
- 缺关键业务决定只询问该问题；阻断只停止依赖部分，继续其他工作。达到本轮验收条件后停止扩展。

当前版本完成规则与引用核对，不将技能静态校验当作真实项目验收。
