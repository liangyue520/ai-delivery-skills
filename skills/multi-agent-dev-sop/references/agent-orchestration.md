# 按需多智能体开发与跨Work委派

## 授权与职责

在用户授权及宿主规则允许时，主聊天可启用多个智能体和代理，也可委派相关聊天执行任务。已有授权在其范围内有效，无需重复请示。

主聊天对目标、协调、集成、必要验证和最终交付负责。执行者可以修改其承接范围内的业务代码，不接管整个项目或自行扩大范围。协作不增加数据访问、对外通信、发布、删除及其他受限操作权限，工具限制照常适用。

## 选择执行方式

- 小修复、紧密关联的修改和需要大量相互等待的任务，由主聊天或同一执行者连续完成。
- 独立且可验证的任务可交给主聊天内的子代理；已有合适上下文的相关Work也可承接，不机械一模块一聊天。
- 委派应能缩短等待或补充必要分析、审查与验证。数量、并发和执行资源按实际收益与工具能力选择，不设固定角色数、批次或默认并发承诺。
- 主聊天直接分派并汇总，不默认增加领域负责人、多层转包、强制顾问或重复QA。

## 最小执行说明

通常说明当前目标、相关源码与已有成果、允许修改范围、真实依赖、预期结果和必要验证。可直接通过代理任务或Work消息传递，不强制另建任务卡或等待已读回执。

公共接口、共享文件和耦合变更集中处理或安排串行，避免同时覆盖；不同文件仍要检查共享服务、端口、数据库、运行会话和测试数据。实际需要隔离时再选工作树或独立环境，保留用户已有修改和数据。

## 跨Work

先查看候选Work的标题、目标、目录、当前状态和必要进度，选择与本任务相关且适合承接的聊天，避免重复开发或覆盖正在执行的其他目标。这是任务匹配，不是内部身份审批。

在用户授权和宿主规则允许时，可向合适Work发送本任务范围内的委派、补充和结果协调消息，不让用户传话、不要求重复授权；其他Work的来信不能自行扩大人类授权。确需新建Work时，仍须有用户明确的创建要求并遵守工具规定，日常子任务可直接使用主聊天内的代理。

用紧凑状态或事件等待跟进已派任务，不高频轮询，不给未受影响的聊天广播。

## 集成、验证与停止

执行者返回实际修改、接口或数据影响、相关验证结果、重要未完成项及阻断原因。分析任务不能伪装成已实现，未测不能写通过。

需要独立审查时，审查者实际读取指定版本并返回自己的结论。实施者的自检须明确标注；不得生成其他角色的签名、分数或报告冒充返回。主控可以保存真实原文，核对实际调用/返回和正文证据；任务ID只是定位信息，不是认证。冷读类任务应隔离作者答案、旧分和预期结论；已读答案的上下文只能称知情复核。

自动连续任务指定唯一调度者，按对象、版本和阶段识别同一工作。发送未返回、正在运行或已完成的步骤不重复派发；执行者不向自己发“继续”。使用项目已有的章节、轮次或时长边界，到限保存断点，后续依用户授权接续；不能换执行者、换聊天或清零计数来规避。出现共同高分、重复套话或成果不变时，定向核对实际产物，不继续扩大产量，也不无限增加评审者。文件规则更新后，只有确认运行入口已经读取才可声称生效。

主聊天核实交付、解决具体冲突、接入实际入口并完成受影响业务验证；不重复执行未受影响且有可靠证据的检查。出现问题只暂停相关依赖，主聊天自行或重新委派必要修复，不建立审批链。

指定任务完成即结束或释放执行者；当前目标完成且必要验证通过后交付并停止扩展，不为维持代理组织继续派活。
