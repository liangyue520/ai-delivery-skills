# 状态、缺陷与必要证据

## 如实说明状态

| 状态 | 可以说明的事实 | 不能替代的事实 |
|---|---|---|
| 已实现 | 代码或产物已完成 | 正式入口接通 |
| 已集成 | 已接入声明的入口 | 业务结果正确 |
| 已验证 | 指定版本、环境、数据上的用例实际通过 | 所有环境和全部数据均通过 |
| 待验证或受阻 | 未执行部分及原因明确 | 已通过 |
| 用户验收 | 用户对指定范围的实际验收 | 未覆盖能力通过 |
| 已发布 | 指定产物部署到目标位置 | 全部功能无缺陷 |

日常修复可由主聊天或受委派执行者实施；主聊天核实实际改动、相关验证和必要集成结果后据实关闭缺陷，不要求独立QA、另一个聊天或角色签字。用户明确指定的外部验收仅按其范围执行，不擅自代替用户验收。

## 必要记录

通常保留目标或问题、版本和环境、输入、预期与实际、通过/失败/未测、必要日志或截图入口，以及重要未完成项。只记录有助于判断结果的内容，可写在现有记录或答复中。

涉及业务运行时按需记录对象ID、修订、运行ID与数据来源。无需源码哈希表、全包一致性报告、角色签字、下游接收条件或专用证据卡。报告不暴露密码、凭据或完整敏感配置。

## 冲突与缺陷修复

先比较是否同一问题、版本、环境、数据与检查范围，再核对实际结果。新“已修复”文字不能代替回归；旧失败也不能掩盖新版本已实测通过的结果。

主聊天自行或委派复现定位和最小必要修复 → 核实集成 → 按需部署 → 受影响回归 → 如实更新状态。仅验证任务发现问题不自动授权修改。已有历史报告不改造成新证据，本次结果另记即可。

关键业务失败不能被多数通过掩盖；健康检查只证明探针，页面有数值不证明数据源真实，构建成功不证明实际运行入口更新。

## 交付

先说明用户当前能操作什么，再说明改动、本次实际验证与重要未完成项。无需维持角色交接链、QA登记表、完成百分比和多份重复报告。

达到本轮目标且必要验证通过就停止，不为补齐材料扩展开发或重跑未受影响检查。
