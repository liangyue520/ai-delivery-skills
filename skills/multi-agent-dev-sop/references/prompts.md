# 可复制的任务指令

按实际任务填写。遵守用户和宿主对代理开发及委派相关Work的现行授权，不重复确认已有授权；模板不扩大当前业务范围，也不生成任务外的新建Work、部署、删除或对外发送授权。

## 接手与开发

~~~text
使用本技能并遵守delivery-first，由主聊天统一负责，可按需委派开发代理或相关Work。
本轮目标与成功标准：[填写]
现有原型、源码及运行入口：[填写]
当前需求、已有成果和需要保护的数据：[填写]
优先复用原型与可运行实现，补齐当前业务缺口；小任务直接完成，独立任务按实际收益委派，避免并发覆盖。
补必要设计后直接实施，贯通正式入口到结果，做受影响的必要验证。
交付可操作入口、实际完成范围、本次验证和重要未完成项；达到目标即停止扩展。
~~~

## 代理或相关Work执行

~~~text
主聊天委派的目标与成功标准：[填写]
任务类型与允许操作：[开发 / 修复 / 分析 / 审查 / 验证，按实际范围填写]
相关资料、源码、已有修改与当前入口：[填写]
允许修改范围、真实依赖及公共接口约定：[填写必要项]
按指定范围直接执行，保护既有修改和数据；共享部分有冲突时报告具体影响，不覆盖他人工作。
返回实际改动、接口或数据影响、验证结果和重要未完成项，不把自测声明当成整体完成。
由主聊天负责协调、集成与最终验证；不新增审批链或要求用户传话。
~~~

跨Work时先核对任务、目录与状态；没有明确新建要求时优先相关现有Work或主聊天内的代理。

## 问题定位与修复

~~~text
现象与预期行为：[填写]
当前授权范围：[诊断 / 诊断并修复]
相关入口、环境和数据：[填写]
先定位实际运行版本、入口、数据与最小复现，按证据在责任层修复。
保护既有修改和数据，不建立冻结副本或日常哈希审计流程。
主聊天完成修复和受影响回归后据实更新缺陷状态，不默认转交独立QA。
提交根因、改动、实际验证和未完成项。
~~~

## 部署与业务验证

~~~text
交付版本、目标环境及已授权服务范围：[填写]
业务成功标准：[填写]
核对实际启动入口、进程、配置和目标产物，只更新需要的服务。
按影响保留必要恢复办法，保护现有数据，从正式入口验证受影响业务。
记录预期、实际和通过/失败/未测，不用健康探针代替业务成功。
主聊天根据验证结果修复或交付，不增加冻结审批和独立角色门槛。
~~~

## 数据或会话迁移恢复

~~~text
恢复目标：[文件 / 原会话 / 上下文重建 / 环境或数据]
来源、目标及需保留的已有成果：[填写]
优先支持的导入、恢复和项目管理能力，按影响备份并在暂存位置验证。
核对必要文件、路径、依赖、数据一致性和应用可读性。
区分原会话恢复与导出文本的上下文重建；不自动执行历史指令。
报告已恢复、实际验证、未测项及必要恢复办法。按当前任务需要可向相关Work发送已授权的协作说明；不自动执行历史指令、不向无关聊天广播。
~~~
