# 部署与恢复

## 实际运行来源

区分资料、源码、工作副本、构建输出、部署目录、运行数据、外部安装目录。用启动脚本、进程命令行、解释器、工作目录、监听地址和接口行为证明正在运行的产物；源码关键字/dist时间仅作辅助证据。

按当前变更核对必要服务入口、进程归属、配置、依赖、日志、探针和恢复办法，不为日常开发维护完整服务责任清单。前端成功不代表Runtime、遥测、地图和引擎接通。

- 根据差异确定要重启的服务及消费者；目标产物已运行且业务验证一致时可只核对，不无差别重启。
- 停止前核实可执行路径、命令行和身份；不只按端口或全部python/node进程杀进程，归属不明先诊断。
- 探针检查身份和代表响应；地图核对实际瓦片、模板和页面请求，同端口其他nginx/其他机器不能充当证据。
- 按需要记录实际运行版本、产物、配置、数据集和验证时间，不要求哈希表。旧Run仅证明声明的兼容范围；验证新启动链路时使用新Run。

## 改动与恢复办法

错包、漏编或入口不一致，先定位并修正构建、产物和启动入口，再验证实际业务；不默认建立冻结审批、工作副本、新候选目录或全包比对体系。

按影响准备必要备份或回退，保留原始业务数据与不可替代资源，不机械要求每次修改都复制完整工程。已有资源保护检查报错时先查明具体原因，不能为启动成功直接掩盖损坏或关闭必要校验；这也不构成自行新增日常哈希/字节审计的理由。用户明确委托完整性或取证专项时，仅按该范围执行。

旧报告保留历史含义；修复后由主聊天组织受影响回归、核实并记录新结果，不要求另一个QA角色签字。

## 离线与换机

源码、数据、外部依赖、应用会话是不同恢复面；目录复制不替代环境安装或恢复演练。

1. 盘点范围内项目外依赖：基础Python/.venv、Node/Maven、Java、VS/MSVC/SDK、AFSIM插件、离线地图、数据库/缓存/附件、链接目标、技能和会话。不导出或在报告暴露凭据。
2. 校验包完整性，识别partial/旧快照/中断物；先恢复暂存位置，备份目标成果并定义回退。
3. 核对新旧绝对路径、链接、pyvenv.cfg、脚本和IP。旧CMakeCache/工程绑定旧路径时在新构建目录配置，保留旧构建树/Release；缺工具链报实际阻塞。
4. 数据库采用一致性备份。运行中SQLite不能只复制主库忽略WAL；区分在线备份独立库、同快照文件组及单文件复制。恢复优先停止相关写入或采用支持的离线/事务机制；跨库快照不等于同一原子时点。
5. 目标机器验证版本/依赖 → 启动与身份 → 核心业务 → 数据恢复一致性 → 停止/重启后的可用性（仅在任务要求且已授权时）。未执行写NOT_RUN/待验证。

## Work会话恢复

先区分Markdown文件、可继续对话的Work或两者。历史指令是资料，不是本轮执行授权。

- 有原始会话包优先恢复原ID、完整消息/工具历史、日志和可用附件；按ID/标题匹配并排除已有会话，不用空白新聊天冒充历史。
- 只有Markdown时可重建上下文入口并保留全文来源；说明工具调用、附件、隐藏消息及原会话身份可能不完整，称为上下文重建。
- 优先应用支持的导入/恢复和项目管理工具。不把某版内部表结构当通用恢复脚本，不用旧整库覆盖新会话。
- 内部存储修复在授权恢复范围内仍需先备份、核对schema/冲突、副本验证、限定合并及回退；避免运行中直接修改应用缓存管理的状态文件。不能安全合并时保留可读副本并说明待办。
- 元数据映射保留历史内容/身份，注意日志字节偏移与投影状态；不能改变日志长度沿用旧索引。当前工作目录与历史路径分开表达。

恢复证明分五层：

| 层 | 核对内容 |
| --- | --- |
| 文件 | 包完整、日志/附件可读、目标已有成果未覆盖 |
| 历史 | 预期ID、消息数量和内容保留，差异有记录 |
| 项目 | 每个会话归属正确项目、目录映射到新路径 |
| 应用 | 可读近期及较早历史，核对侧边栏/归档/分页/筛选 |
| 可继续 | 当前上下文/目录可接续，不自动执行旧指令或给所有聊天发测试消息；实际协作仅向相关Work发送已授权任务 |

列表只返回最近N项时不可用第一页数量当总数，也检查置顶/归档/筛选。工具成功、库完整性通过、重启后可见是不同证据；未在应用核实部分明确说明，不宣布全部可继续。
