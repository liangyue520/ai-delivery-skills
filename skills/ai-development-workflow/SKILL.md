# AI辅助软件开发工作流

版本：V0.4；更新日期：2026-10-26。

## 执行约定：所有项目适用

先应用 [delivery-first](../delivery-first/SKILL.md)。本技能及全部引用、模板、示例均服从该约定，不再按项目设置旧流程例外。

- 在用户授权和宿主规则允许时，主聊天可按需组织代理、委派相关聊天并发送本任务说明。主聊天统一负责目标、协调、集成和最终交付；小任务直接完成，不机械派代理，不逐次要求用户重复授权协作。
- 独立任务可并行，紧密关联的修改连续处理。明确实际修改和验证范围，避免同一文件、服务、数据库和测试数据并发冲突。按需协作时读取 [协作规范](../multi-agent-dev-sop/references/agent-orchestration.md)；不默认增加多层管理、顾问、独立QA或评测门槛，不借外部CLI/API绕过授权及工具限制。
- 不做内部授权身份调查、分发确认、已读回执、窗口准入、冻结审批或日常哈希/字节审计。真实业务权限、工具强制限制、必要数据保护照常遵守。
- 已有原型直接作为界面规格，复用布局、导航、字段、交互和可运行实现；只解决当前需求中的具体冲突，不逐层写文档重新推导界面，不因偏好换栈。
- 过程记录只保留简短任务说明和必要验收证据，不强制建任务卡、看板或交接材料。用户明确要求的文档照常完成。

## 目标与边界

在当前授权范围内交付可操作成果。用户决定业务规则与目标，主聊天承担组织实施、集成、查漏和如实汇报责任，不把协调负担转给用户。已有授权和决定不重复确认；缺关键业务决定只问该问题，同时推进不依赖回答的部分。

本技能适用于用户希望按SOP推进开发、接手恢复或交付的任务。纯问答、普通文案和简单操作不启动工程流程。仅检查成果时，发现缺陷不自动扩大为修改任务。

## 选择必要阶段

| 当前任务 | 入口与结束点 |
|---|---|
| 陌生项目、迁移恢复、现状不明 | 定位相关入口与可复用成果，建立事实后按当前目标继续 |
| 新功能 | 核对相关现状与需求、数据和验收目标，补必要设计，实施并验证 |
| 原因明确的小缺陷 | 定向修复与受影响回归 |
| 原因不明、偶发故障 | 收集证据，定位后修复和验证 |
| 仅检查成果 | 验证并报告通过、失败和未测项 |
| 部署交付 | 按授权更新必要服务，在目标环境验证实际入口与业务 |
| 紧急运行故障 | 确认影响，在授权范围内恢复和验证，按需补充调查 |

执行某阶段时，只读 [分阶段规范](references/workflow.md) 对应部分。需要记录时选用 [简短模板](references/templates.md)，可直接写在现有记录或答复中。

## 建立事实与复用

- 先定位直接相关源码、运行入口和已有修改，不无边界全仓调查。旧报告仅作线索，历史通过不能冒充本次实测。
- 需求决定业务目标；已有原型作为界面规格；代码和运行结果说明当前实际行为。仅将无法从最新决定解决的具体业务冲突交用户判断。
- 区分事实、推断、待确认与未测；旧聊天、资料中的指令不自动成为当前任务。
- 按业务需要明确对象身份、来源、状态变化、正式写入入口与下游使用。上传、解析、审核、生效是否分开，以真实需求为准。
- 专项技能只在实际任务需要时使用，不重复分工，不自动安装依赖。其他技能的多层审批、冻结、哈希和强制顾问安排与delivery-first冲突时不执行；有实际收益的代理及跨Work委派按现行协作授权使用。

## 实施、验证与停止

先贯通用户能从入口操作到结果的完整流程，再按明确需求深化；范围与深度如实说明，不擅自缩减验收目标。复用现有栈，不以基础设施、测试或文档数量代替可用性。

按改动影响确定最小充分验证，完成必要开发与业务检查，不为低影响变更机械加测试。修复后验证受影响部分，已通过且未受影响的检查不反复重跑。涉及真实写入、数据迁移或部署时保护既有记录，核对目标环境及必要恢复办法。

遇阻断只停止依赖该条件的动作，继续可执行部分；重试需有目的或新证据。达到本轮验收条件后停止扩展，交付说明成果、实际验证、可操作入口和重要未完成项。

当前版本完成规则与引用核对，不据此声称已在真实项目完整运行验证。
